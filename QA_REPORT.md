# QA / архитектурный аудит Almazov Universal Schedule Hub

Дата проверки: 2026-10-04
Релиз: 1.1.1 / QA3  
Контур: статический код, данные, календарная логика, адаптивность CSS, схема обновления и официальные источники ИМО НМИЦ им. В.А. Алмазова.

## 1. Главная причина предыдущих проблем

Старый сервис был построен вокруг одного live-источника Лечебного дела и частично размазанных ручных исключений. Для новых направлений это давало два типа ошибок:

1. расписание программы могло вообще не попадать в нормализованный слой;
2. числовой индекс дня недели ручных правил и индекс рендера могли не совпадать, из-за чего занятия уезжали на неверный день.

Отдельная опасная ошибка была в автоматическом определении учебной недели: событие без однозначной даты могло попасть в текущую неделю. Это является источником «бесконечных» повторов при грязных/неполных данных.

## 2. Новая модель

Сервис разделяет:

- каталог: факультет → программа → курс → группа;
- расписание: лекция / ПЗ → дата → время → группа;
- КУГ: независимый календарный слой;
- источники: оригинальные страницы/PDF/JSON;
- ДЗ: отдельный локальный пользовательский контур.

Ни одно событие не показывается в конкретной группе без строгой привязки к группе. Неопределённая неделя больше не подставляется автоматически.

## 3. Покрытие

Поддержаны как реальные расписательные программы:

- 31.05.01 Лечебное дело: 1-6 курсы, live-источник;
- 31.05.02 Педиатрия: 1-2 курсы, официальный PDF snapshot;
- 37.05.01 Клиническая психология: 1-2 курсы, официальный PDF snapshot.

Каталог также содержит 6 факультетов и дополнительные уровни образования, но расписательные данные для них не выдумываются.

## 5. Обновление

GitHub Actions:

- синхронизирует live snapshot каждые 6 часов;
- валидирует live JSON после загрузки;
- валидирует локальные адаптеры;
- коммитит только изменившийся snapshot;
- при ошибке remote не заменяет рабочие данные пустым/битым файлом.

PWA shell кешируется отдельно. Live snapshot не кешируется принудительно, чтобы сеть могла получить свежий индекс.

## 6. Известные ограничения

Официальная страница электронного расписания сообщает, что сервис ИМО находится в тестовом режиме и может не отражать выполненные переносы.

Для Педиатрии и Клинической психологии текущая версия использует проверенные официальные PDF как snapshot. Для автоматического обновления этих направлений без ручной перекодировки нужен отдельный серверный PDF/parser-adapter и контроль изменения исходного документа.

ДЗ/задачи сейчас локальные: они не синхронизируются между устройствами и не требуют авторизации. Это сделано как безопасный offline-first MVP; для полноценной многодевайсной версии нужен backend + аккаунт студента.

Исправлены дополнительные дефекты, найденные после предыдущего релиза:

Официальная страница кабинета студента на 2026/27 содержит отдельные расписательные контуры для Лечебного дела, Педиатрии и Клинической психологии; для Педиатрии и Клинической психологии опубликованы 1-2 курсы, для ЛД — 1-6. ## QA3.2 / 2026-10-06

### Root cause fixed

For first-year LD groups, some lecture events are published with `group=ALL` and a stream marker. The previous client filtered by group only, so a group from stream B could receive stream A lectures. The 1.2.0 release resolves the selected stream from `course.streams` and requires stream compatibility for every event.

### UX changes

The square time-grid is no longer used by the schedule page. It is replaced with a semantic weekly agenda: each day is a column containing ordered lesson cards. Breakpoints switch from 7 columns on desktop to 4/2/1 columns on smaller screens. Search, share-link, source status, and explicit empty states were added.

### Automated assertions

Added stream A/B isolation tests, `ALL` lecture tests, Unicode/case dedupe, stricter live-schema validation, and responsive contract checks.
