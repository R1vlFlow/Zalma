# Zalma 2.5.0 — Phase 2

## Added
- Telegram technical support link `https://t.me/R1vlFlow_GY` in navigation, profile and settings.
- Personal materials upload to IndexedDB: PDF, DOCX, XLSX, PPTX, ZIP, JPG/JPEG and PNG; 25 MiB per file; scoped by program/course/group.
- Themed custom select and date/time controls with keyboard operation, month navigation, weekend/today states and cues for outstanding homework deadlines.
- Dashboard class focus/countdown, today's timeline, nearest three unfinished homework deadlines and quick actions.
- “Записать ДЗ” actions on schedule cards that preselect the subject and look for the next scheduled occurrence to suggest a due date.
- Data-schema v2 normalization plus a one-time copy of the previous central personalization JSON before upgrade.
- Parser anomaly logging for invalid durations and suspicious long schedule blocks; known 185/205-minute blocks preserve both split parts.

## Data retention contract
- Deploying new static assets does not clear `localStorage` or IndexedDB.
- Legacy profile, tasks and materials keys are preserved; migration reads and copies them into the centralized store rather than deleting them.
- When upgrading an existing pre-v2 central payload, a raw copy is written to `almazov.backup.personalization.pre-v2` before normalized data replaces it. If the backup cannot be stored due to quota, the original central key is left unchanged and writes are blocked for the session.
- Uploaded binary files are device/browser-local IndexedDB records, not cloud-synced files. Clearing site storage, browser profile removal or changing devices can remove/make those files unavailable; export/sync backend is not included in Phase 2.

## Run and verify
```sh
npm install
npm run qa
npm start
```

Node 22.5+ is required. The official schedule and KUG source files remain the existing project inputs; no new unofficial schedule data is generated by these UI changes.
