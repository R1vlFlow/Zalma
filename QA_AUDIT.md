# Almazov Student PRE-RELEASE 2.0.2 — QA/Audit

Дата аудита: 2026-10-04

## 1. Найденная причина «бесконечной химии» по понедельникам

В исходной логике автоматической сборки официального расписания существовал опасный fallback:

`if (!start) start = isoDate(startOfWeek(new Date()));`

То есть запись, у которой отсутствовали одновременно `weekStart` и `date/dateHint`, безусловно попадала в текущую календарную неделю. Для данных, содержащих `weekNumber`, это могло смешать занятия нескольких учебных недель в один понедельник. При большом количестве записей одного предмета визуально это выглядело как бесконечный список химии.

Исправление:
- `weekStart` используется первым источником;
- затем неделя выводится из `date/dateHint`;
- затем `weekNumber` восстанавливается относительно ближайшей известной недели;
- если учебную неделю определить нельзя, событие не попадает в текущую неделю и пропускается с диагностикой в console;
- добавлена дедупликация событий по семантическому ключу;
- старые автоматически синхронизированные расписания версии до `scheduleFixVersion=3` принудительно пересобираются при следующей успешной синхронизации.

## 2. Сдвоенные пары

Проверено, что повторный вызов `ensureRenderableSchedule()` не размножает пары.

Стресс-тест: 100 последовательных вызовов над одной 205-минутной парой.

Результат: стабильно 2 события — `09:00–10:35` и `10:50–12:25`; дальнейшего роста массива нет.

Также сохранено важное правило: две реальные соседние пары одного предмета не объединяются и не удаляются как дубликаты. Дедупликация удаляет только семантически одинаковые записи.

## 3. Проверка распределения по неделям

Тест с одной корректной опорной записью (`weekNumber=2`, `weekStart=2026-09-07`) и шестью событиями только с `weekNumber=3..8` дал семь отдельных недель: 2026-09-07, 09-14, 09-21, 09-28, 10-05, 10-12, 10-19.

Тест без единой опорной даты/недели дал 0 созданных недель и 6 пропущенных событий. Главное: такие события больше не сваливаются в текущий понедельник.

## 4. Адаптивность

Браузерный layout-тест проведён на 11 размерах:

- 320×568
- 360×800
- 390×844
- 412×915
- 600×960
- 768×1024
- 834×1194
- 1024×768
- 1280×800
- 1440×900
- 1920×1080

На всех проверенных размерах `documentElement.scrollWidth` и `body.scrollWidth` не превышали ширину viewport.

Недельная сетка намеренно сохраняет минимальную ширину и прокручивается внутри `.week-scroll`; это предотвращает появление горизонтального скролла всей страницы на телефоне.

## 5. Синтаксис и структура

Все 7 inline JavaScript-блоков исходного `index.html` прошли `node --check`.

`sw.js` также проходит синтаксическую проверку Node.

Дублирующихся HTML `id` не обнаружено.

Ссылки `target="_blank"` проверены: отсутствуют ссылки без `noopener`.

В CSS присутствуют 37 media-query блоков; основные переломы рассчитаны под мобильные, планшетные, ноутбучные и широкие экраны.

## 6. Исправления релизной инфраструктуры

В исходном ZIP были заявлены, но фактически отсутствовали несколько PWA/runtime-файлов. Добавлены:

- `manifest.webmanifest`
- `sw.js`
- `version.json`
- `logo-512.png`

Также исправлена ссылка основного логотипа: приложение больше не пытается загрузить отсутствующий `logo.webp`.

Проверены и добавлены квадратный PWA/Apple-touch icon 512×512 и корректная регистрация Service Worker.

## 7. Состояние официального источника

На момент аудита актуальный `official-schedules.json` в GitHub имеет `schemaVersion=7` и `generatedAt=2026-10-01T07:16:44.137234+00:00`. Источник содержит курсы 1–6 и отдельные roster/stream данные. Для группы 123 по 1 курсу в текущих данных присутствуют отдельные понедельничные записи химии с явными `date`, `weekNumber`, `weekStart`, а сдвоенные записи имеют `double`, `doubleIndex` и `doubleOf`.

Следовательно, текущий JSON сам по себе содержит достаточно данных для корректного определения недели; критичная проблема была в клиентском fallback на «текущую неделю» при неполной записи.

## 8. Важное ограничение поставки

Исходный ZIP не содержит каталога `data/official-schedules.json` и GitHub Actions workflow, хотя README рассчитывает на них. Поэтому архив остаётся зависимым от доступного официального remote-источника для полной автоматической синхронизации расписания.

Я намеренно не добавлял урезанный или частично скачанный `official-schedules.json`: это было бы хуже для точности, чем явный remote fallback.

## 9. Вторичные замечания

В форме приложения есть элементы, у которых доступное имя задаётся визуальным контекстом, но не всегда явным `aria-label`/связью `label[for]`. Это не является причиной бага расписания, но остаётся задачей для отдельного accessibility-прохода.

Используются внешние CDN-зависимости (JSZip, Mammoth, Tesseract.js, XLSX, pdf.js). Для production-развёртывания стоит рассмотреть локальное бандлирование/версионирование зависимостей и SRI, чтобы снизить зависимость от внешней сети.

## Итог

Критическая логическая ошибка с потерей привязки событий к учебной неделе устранена. Защита от повторного размножения сдвоенных пар и семантических дублей добавлена. Адаптивный layout проверен на телефонах, планшетах, ноутбуках и широких десктопах; внешнего горизонтального overflow на проверенных размерах не обнаружено.
